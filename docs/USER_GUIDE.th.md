# คู่มือการใช้งาน CoreAlign TMA v2.0.0

**รันครั้งเดียว ตอบสองครั้ง แล้วเอาไฟล์ไปใช้**

CoreAlign หาตำแหน่ง core ทั้งแผ่น หมุนทุก core ให้เนื้อเยื่อหันทางเดียวกัน ครอป แล้วส่งออกไฟล์
ก่อนเริ่มถามสองข้อ ระหว่างทำงานถามอีกสองครั้ง นอกจากนี้ไม่มีอะไรต้องเรียนรู้เพิ่ม

---

## ภาพรวมทั้งกระบวนการ

```
รันสคริปต์  →  เลือก 2 ตัวเลือก กด Start  →  ⏸ ตรวจ grid กด Continue
            →  ⏸ ตรวจ core ที่หมุนแล้ว กด Approve  →  ✅ ได้ไฟล์
```

**ไม่ต้องกลับไปที่หน้าต่าง script editor อีกเลย** จุดที่หยุดรอทั้งสองจุด ตอบได้ที่หน้า
`REPORT.html` บนเบราว์เซอร์ หรือที่หน้าต่างเล็กของ CoreAlign ใน QuPath ก็ได้ ตอบที่ไหนก็ได้
งานเดิมจะเดินต่อทันทีจากคำตอบนั้น

---

## สิ่งที่ต้องมี

| สิ่งที่ต้องมี | รายละเอียด |
|---|---|
| QuPath | 0.7 ขึ้นไป |
| สไลด์ | ไฟล์ whole slide ที่ QuPath เปิดได้ อยู่บนเครื่อง |
| พื้นที่ว่าง | พอสำหรับ channel ที่เลือกและไฟล์ผลลัพธ์ทั้งหมด |
| ตัวสคริปต์ | `CoreAlign.groovy` ไฟล์เดียว ไม่ต้องติดตั้งอะไรเพิ่ม |

---

## ขั้นตอนที่ 1 · วางของสามอย่างไว้ในโฟลเดอร์เดียว

สร้างโฟลเดอร์เปล่าใหม่ แล้ววาง **สไลด์** กับ **`CoreAlign.groovy`** ไว้ด้วยกัน ไม่ต้องมีอะไรอีก

🔴 **กับดักที่เจอบ่อยที่สุด** · CoreAlign เขียนผลลัพธ์ทุกอย่างไว้ข้าง ๆ สไลด์ที่ **เปิดอยู่จริง**
ถ้าเผลอเปิดสไลด์อีกก๊อปปี้จาก Downloads ผลลัพธ์จะไปโผล่ที่นั่น ไม่ได้อยู่ในโฟลเดอร์ที่ตั้งใจ

ไฟล์ config ไม่จำเป็นต้องเตรียม · CoreAlign เขียนให้เองในการรันครั้งแรก

---

## ขั้นตอนที่ 2 · เปิดสไลด์แล้วรันสคริปต์

1. เปิด QuPath แล้วเปิดสไลด์จากโฟลเดอร์ที่เตรียมไว้
2. เมนู **Automate** → **Show script editor**
3. เปิดไฟล์ `CoreAlign.groovy` แล้วกด **Run**

---

## ขั้นตอนที่ 3 · ตอบสองข้อ แล้วกด Start

หน้าต่างตั้งค่าจะขึ้นมาหน้าเดียว มีสองแถวให้เลือก และปุ่มเดียวให้กด

| หัวข้อ | ตัวเลือก | ความหมาย |
|---|---|---|
| **Tissue** | `Skin` | หมุนให้ **epidermis อยู่ด้านบน** ทุก core |
| | `Other tissue` | หมุนให้ **ขอบเนื้อเยื่อที่ชัดที่สุดอยู่ด้านบน** |
| **Results** | `Images` | ได้ PNG ความละเอียดเต็ม · เร็วกว่า |
| | `Images + research files` | ได้ PNG + OME-TIFF หลาย channel + โปรเจกต์ QuPath |

**จำนวนแถว จำนวนคอลัมน์ ขนาด core และตำแหน่ง array ระบบวัดเองจากสไลด์** จึงไม่มีช่องให้กรอก
และไม่ต้องเดา

เปลี่ยน **Results** ทีหลังได้ โดยไม่ต้องทำงานที่อนุมัติไปแล้วซ้ำ

กด **Start**

---

## ขั้นตอนที่ 4 · ⏸ ตรวจว่าหา core ครบไหม

พอตรวจจับเสร็จ `REPORT.html` จะเปิดขึ้นเอง ด้านบนมีแถบสีเหลืองเขียนว่า **QuPath is waiting for you**
พร้อมตัวเลข เช่น *117 cores found, 9 positions empty*

| สถานการณ์ | ทำอย่างไร |
|---|---|
| วงกลมครบทุก core ถูกต้อง | กด **Grid is correct** |
| มี core ที่ระบบหาไม่เจอ | ใน QuPath วาด **ellipse** ทับ core นั้น ตั้งชื่อว่า `TMA correction` แล้วกด **Grid is correct** |
| ตำแหน่งนั้นว่างจริง ๆ | วาด ellipse ตั้งชื่อว่า `TMA mark missing` |
| ระบุตำแหน่งเองให้ชัด | ใส่ตำแหน่งท้ายชื่อ เช่น `TMA correction 4-C` |

**ถ้ามีการแก้ไข CoreAlign จะไม่อนุมัติในรอบเดียวกัน** · ระบบจะใส่การแก้ไข วาดภาพ QC ใหม่
แล้วเปิดให้ดูอีกรอบก่อนไปต่อ เป็นการป้องกันการอนุมัติภาพที่ยังไม่ได้เห็น ไม่ใช่ข้อผิดพลาด

สีในภาพ QC · **ฟ้า** = ระบบหาเอง · **เขียว** = คนแก้ไข · **แดง** = ว่าง

---

## ขั้นตอนที่ 5 · ปล่อยให้หมุนและครอป

แต่ละ core จะถูกจัดตำแหน่ง **หมุนก่อน แล้วค่อยครอป** ตามลำดับนี้เสมอ และบันทึก checkpoint
หลังทุก core

- ระหว่างนี้ใช้ QuPath ทำอย่างอื่นได้ตามปกติ
- ถ้า QuPath ปิดไประหว่างทาง ให้เปิดสไลด์เดิมแล้วรันสคริปต์ใหม่ · ระบบทำต่อจาก core สุดท้ายที่บันทึกไว้
  ไม่ได้เริ่มใหม่ทั้งหมด

---

## ขั้นตอนที่ 6 · ⏸ ตรวจ core ที่หมุนแล้ว แล้วอนุมัติ

หน้า report จะเต็มไปด้วยการ์ด core ละใบ

| สีขอบบน | ความหมาย | ทำอย่างไร |
|---|---|---|
| เขียว | ผ่าน QC อัตโนมัติ | ดูผ่าน ๆ แล้วกด **Confirm** |
| เหลือง | ระบบไม่มั่นใจ ต้องให้คนดู | ถ้าถูกกด **Confirm** · ถ้าผิดกด **Edit** ลากปรับมุม แล้วกด **Update** |
| แดง | ว่าง หรือประมวลผลไม่สำเร็จ | ตรวจว่าตำแหน่งนั้นว่างจริงไหม |
| ม่วง | มีการแก้มุมที่ยังไม่ประมวลผล | ระบบจะทำเฉพาะ core เหล่านี้ซ้ำให้ |

มุมที่แก้จะ **บันทึกเองอัตโนมัติ** ไม่ต้องกดเซฟ

พอพอใจแล้ว กด **Approve and finish** ที่แถบด้านบนของหน้า

ถ้ามีการแก้มุม CoreAlign จะประมวลผลเฉพาะ core ที่เปลี่ยน แล้วเปิดให้ดูผลใหม่อีกครั้ง
core ที่ยืนยันไปแล้วจะไม่ถูกทำซ้ำ

---

## ขั้นตอนที่ 7 · เอาไฟล์ไปใช้

```
โฟลเดอร์งานของคุณ/
├── slide.ome.tif
├── CoreAlign.groovy
├── corealign.config.json     ← ระบบเขียนให้เองรอบแรก
├── REPORT.html               ← หน้าเดียวที่ต้องเปิด
├── qc/
│   ├── 01-grid/              ภาพตรวจจับทั้งแผ่น + พิกัด
│   └── 02-orientation/       ภาพตัวอย่างราย core + contact sheet
├── results/
│   ├── png/                  ภาพความละเอียดเต็ม core ละไฟล์
│   ├── ome-tiff/             เฉพาะโหมด Research
│   └── tables/               CSV และ JSON สำหรับตรวจย้อนหลัง
├── qupath/                   โปรเจกต์เรียงตามแถว เฉพาะโหมด Research
└── work/                     checkpoint · 🔴 ห้ามลบ
```

**`work/` ห้ามลบ** · ในนั้นคือ checkpoint ที่ทำให้อัปเกรดจาก Images เป็น Research ทีหลังได้
โดยไม่ต้องประมวลผลใหม่ ถ้าลบไปแล้วต้องเริ่มจากศูนย์

## คำอธิบายชื่อ annotation ทั้งหมด

วาดรูปทรงใน QuPath แล้วตั้งชื่อตามตารางนี้ · CoreAlign จะจับเข้ากับ lattice ของ array
แล้วหาแถวกับคอลัมน์ให้เอง

| ตั้งชื่อว่า | ใครวาด | ทำอะไร |
|---|---|---|
| `TMA correction 4-C` | คุณ | ใส่ core ที่ระบบหาไม่เจอ หรือย้าย core ที่วางผิดที่ |
| `TMA mark missing 14-G` | คุณ | ยืนยันว่าตำแหน่งนี้ว่างจริง |
| `TMA crop override 4-C` | คุณ | กำหนดกรอบครอปเองแทนที่ระบบเลือก |
| `Epidermis override 4-C` | คุณ | ชี้ว่าด้าน epidermis อยู่ทางไหน เมื่อระบบหมุนผิดทาง |
| `TMA orientation 4-C` | CoreAlign | แสดงกรอบจริงที่ใช้หมุนและครอป · ไม่ต้องแก้ |

## ปัญหาที่เจอจริง และวิธีแก้

**ปุ่มบนหน้า report บอกว่าติดต่อ QuPath ไม่ได้**
เปิด QuPath ค้างไว้แล้วกดใหม่ · ถ้ายังไม่ได้ ใช้ปุ่ม **Continue** ที่หน้าต่างเล็กของ CoreAlign แทน
ทำงานเหมือนกันทุกอย่าง

**เผลอปิดหน้า report ไป**
กด **Open report** ที่หน้าต่างเล็กของ CoreAlign หรือเปิด `REPORT.html` จากโฟลเดอร์งานเอง
งานยังรออยู่ ไม่ได้หายไปไหน

**QuPath ปิดกลางคันตอนรันยาว ๆ**
เปิดสไลด์เดิมแล้วรันสคริปต์ใหม่ · core ที่ทำเสร็จแล้วจะไม่ถูกทำซ้ำ

**ระบบหยุดแล้วบอกว่า structural QC failed**
แปลว่าเจอ core น้อยเกินกว่าจะเชื่อว่าเป็น array หรือมีแถว/คอลัมน์ว่างทั้งแถว ให้ดูภาพ QC
เพิ่ม `TMA correction` แล้วรันใหม่

**เลือก Images ไปแล้ว แต่ต้องการ OME-TIFF**
เปิด report สลับ **Results** เป็น **Research** แล้วรันสคริปต์อีกรอบ · การตรวจจับ การหมุน
และการครอป ถูกนำกลับมาใช้ทั้งหมด ระบบสร้างเฉพาะไฟล์ที่ยังไม่มี

**อยากเปลี่ยนชนิดเนื้อเยื่อหลังเริ่มไปแล้ว**
รันสคริปต์ใหม่แล้วเปลี่ยนในหน้าตั้งค่า · การเปลี่ยน tissue เปลี่ยนวิธีหมุน orientation จึงถูกคำนวณใหม่
แต่ grid ที่อนุมัติแล้วยังถูกเก็บไว้

**ชื่อ channel ในสไลด์ไม่ใช่ชื่อมาตรฐาน**
เป็นกรณีเดียวที่ยังต้องใช้ [Config Builder](https://hengkp.github.io/corealign-tma/config-builder/)
สร้าง config แล้ววางไว้ข้างสไลด์

## ข้อจำกัดที่ต้องรู้ก่อนนำไปเผยแพร่

CoreAlign เป็นซอฟต์แวร์สำหรับงานวิจัยและการควบคุมคุณภาพ

- **"เสร็จสมบูรณ์" ในระบบนี้แปลว่า** ทุกตำแหน่งผ่านการตรวจโดยคน และ hash ของ grid กับผลลัพธ์
  ถูกอนุมัติแล้ว · **ไม่ได้แปลว่าการตรวจจับถูกต้องโดยไม่ต้องมีคนตรวจ**
- การอ้างผลในเชิงคลินิกต้องผ่านการตรวจสอบโดยพยาธิแพทย์อิสระ และการ validate ในหน่วยงานของตนเอง
- ห้ามเผยแพร่ข้อมูลสไลด์หรือ annotation ที่ระบุตัวผู้ป่วยได้
